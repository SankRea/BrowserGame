旧版第一张挑战图偏简单；后两张有取舍，但目标路线过长、转弯过多。新版把蓝线改成直线、L 形和 U 形，把需要比较的选择留在支路中。

“最优布局数”计算具体格子组合；把同一条无分叉通道中的等价落墙位置合并后，三张图分别有 1、4、9 类最优方案。

## 模拟方式与局限

1. 独立求解器把支路看成无向图，要求每片剩余连通空地至多接触一个蓝色格子。
2. 合并没有分叉、没有蓝线接点的通道中间格，保留等价位置数量。逐步增加墙数，搜索全部最优方案，并用互不重叠的反例路径提供剪枝下界。
3. 将求得的布局交给游戏现有的“删除蓝线边再搜索”判定器，交叉核对是否只剩唯一有效路线。
4. 贪心基准每次放置使“仍相互连通的蓝线接点对”减少最多的一堵墙。表中的用墙数在同分时按格子顺序选择；额外检查则遍历能通向最优解的所有同分分支。
5. 在 6 张小型入门图上逐格穷举所有预算内布局，核对求解器的最少墙数、具体布局数和独立判定依据。

这些数据支持“目标更易读、需要全局取舍”，不能直接证明真人觉得很难。这里只排除了一类贪心策略，没有排除其他直观解题技巧。搜索节点数、毫秒耗时和解的数量都不直接当作真人难度等级；没有据此估计通关时间。

## 复现

在项目根目录运行：

```powershell
npm.cmd run analyze:only-path
npm.cmd run test:only-path
```

分析命令只读取地图并输出报告，不修改地图、存档或 Git 仓库。当前测试涵盖小图穷举对照、新图预算最小性、有效反例、目标路线最多两次转弯以及贪心策略无法达到最优。

原始数据见 [only-path-analysis.json](only-path-analysis.json)，包含改动前后记录和参考解，**有剧透**。这次已运行 Node 关卡模拟和测试；未构建网站、未进行浏览器交互试玩，也未提交或上传。
