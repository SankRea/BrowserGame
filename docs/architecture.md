# 工程结构与修改入口

项目使用 Vite 多页面入口和浏览器原生 ES Modules。当前游戏不需要组件框架：HTML 负责语义结构，CSS 负责视觉，JavaScript 模块负责行为。生产产物仍是纯静态文件。

## 目录职责

| 位置                         | 职责                                       |
| ---------------------------- | ------------------------------------------ |
| `index.html`、`pages/*.html` | 页面入口、可访问性标记、游戏控制面板的结构 |
| `src/app/catalog.js`         | 游戏标题、介绍、入口、封面类型和首页推荐项 |
| `src/app/home.js`            | 根据目录生成大厅，不包含游戏运行逻辑       |
| `src/shared/site.js`         | 统一的页头、页脚和相对路径处理             |
| `src/shared/storage.js`      | JSON 存储，处理权限、配额和损坏数据        |
| `src/styles/base.css`        | 公共颜色、字体、导航、页脚和基础响应式规则 |
| `src/styles/home.css`        | 大厅专用样式                               |
| `src/games/<game>/`          | 各游戏独立的配置、逻辑、交互和样式         |
| `public/`                    | 原样复制到发布目录的静态资源与许可文件     |
| `vite.config.js`             | 页面构建入口、开发端口、发布路径           |

## 小恐龙模块

- `config.js`：速度、重力、跳跃高度、障碍间距、精灵裁切和碰撞区域。调手感优先修改这里。
- `engine.js`：游戏状态、运动、障碍生成、碰撞、得分。无 DOM、Canvas 或存储依赖。
- `renderer.js`：加载本地精灵图并绘制画面，适配设备像素密度，不修改游戏状态。大厅封面复用静态预览函数。
- `input.js`：把键盘、触屏、多指按住与辅助按钮操作转换成游戏动作，释放和取消输入时清理按键状态。
- `index.js`：将以上模块与页面连接，管理动画循环、暂停、最高分、提示和热更新清理。
- `styles.css`：小恐龙页面布局与触屏按钮。

状态变化为 `ready → running → over`，游戏中可以 `running ↔ paused`。重新开始会重置本局状态，但保留最高分。

物理计算采用秒和世界像素，每步固定为 1/120 秒；`requestAnimationFrame` 只负责调度。每帧积累时间后执行固定步数，限制单帧追赶量，切换标签或失去焦点时自动暂停。障碍生成间距随速度增长，并保留跳跃、落地和再次反应的时间。实际手感仍需要运行后体验调整。

Canvas 的显示尺寸与逻辑坐标分开：设备像素比只影响绘制清晰度，窄屏改变可视宽度。游戏中改变画面比例会暂停，避免视野突然变化时碰撞。

## 数独模块

- `config.js`：难度、位掩码和保存键。
- `engine.js`：行列宫关系、求解与唯一解检查、随机出题。
- `index.js`：棋盘、笔记、撤销、提示、计时和保存恢复。
- `styles.css`：数独棋盘及移动端输入面板。

数独保留原保存键 `playroom.sudoku.v1`。同一来源下的原进度可恢复；`file://`、不同开发端口和发布域名的浏览器存储彼此独立。撤销历史只保存在本次页面内存中。

## 唯一的路模块

- `levels.js`：保留 8 个入门关卡并汇总关卡列表；`challenge-levels.js`：3 张清晰目标路线与复杂支路组成的地图、总墙预算与思路提示。
- `engine.js`：解析棋盘、校验蓝色路线与总墙预算、使用广度优先搜索查找反例并判断唯一性，无 DOM 或存储依赖。
- `renderer.js`：可访问的按钮棋盘与 SVG 路线叠层，按棋盘坐标缩放。
- `progress.js`：校验本地存档，保存每关草稿与已通过方案。
- `index.js`：墙的编辑、撤销重做、检查反馈、关卡导航、键盘快捷键与事件清理。
- `preview.js`：大厅使用的轻量 SVG 封面，不加载控制器和关卡求解。
- `config.js`、`styles.css`：保存键、历史上限和页面样式。

`scripts/analyze-only-path.mjs` 提供独立的最少墙数求解与贪心模拟；`tests/only-path.test.mjs` 用逐格穷举校验求解器，并守住挑战关的路线可读性与预算要求。

规则、唯一性判定依据与关卡编写方式见 [唯一的路说明](only-path.md)。

## 添加新游戏

1. 创建 `src/games/<id>/`，用独立 `index.js` 作为游戏入口。
2. 创建 `pages/<id>.html`，设置 `data-root="../"`，使用 `type="module"` 引用入口。
3. 入口导入公共样式，通过 `mountSiteChrome()` 使用统一导航和页脚。
4. 在 `src/app/catalog.js` 增加游戏描述和 `href`，替换一个预留位置即可。
5. 在 `vite.config.js` 的 `build.rolldownOptions.input` 注册新 HTML 页面。
6. 使用 `public/assets/<id>/` 存放需要原样发布的资源，并记录第三方来源和许可。

游戏之间通过大厅导航连接，不互相导入游戏控制器。可复用的纯函数或界面再放入 `shared/`，不要把游戏特有状态放在公共目录。

## 编码约定

- 文件名采用小写短横线，函数和变量采用 camelCase，类采用 PascalCase。
- 显式 `import` / `export`；单个模块只负责一类事情，不通过 `window` 共享游戏状态。
- 用户可调整的数值集中在配置模块，DOM 文本与样式留在界面层。
- Prettier 统一两空格、单引号、分号和 LF 换行；ESLint 检查未定义变量、无用变量等问题。
- 新增事件监听或动画循环时考虑销毁、暂停和热更新后的清理。
- 修改规则或交互后，在授权运行验证时检查正常流程、失败、暂停恢复、触屏和资源加载失败。
