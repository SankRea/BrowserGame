# 唯一的路：规则与关卡编辑

这是游戏大厅的第三款游戏。玩家在白色空地放置有限数量的墙，让预先标出的蓝色路线成为起点到终点的唯一有效路线。

## 当前范围

- 13 个固定关卡：8 个入门关保持原地图与预算，新增 5 个 9 × 9 挑战关。
- 入门练习独立绕路、共享岔口、转角捷径与死胡同；挑战关包含两侧多出口、错位岔口、内环和交叉连接。
- 不计时、不限制检查次数，所有关卡都可以直接选择。
- 路线只能四方向相邻移动，不能重复经过格子。走进死胡同再折返不算新路线。
- 蓝色路线、起终点和灰色固定障碍不可编辑；墙的数量是上限，不要求花光。
- 挑战关的 `○` 格可通行但不能筑墙，不属于指定蓝线。行列限额只计算玩家放置的墙，跨越不同通道也共用同一行或列的名额。
- 超过行列限额时拒绝本次放置，并说明冲突位置；可以随时收回已有的墙。检查器和存档读取也执行同样的限额规则。
- 修改、撤销或重做后，旧的反例立即清除。每次检查展示一条反例，直到没有其他有效路线。
- 通过记录保存实际使用的墙；再次通过且墙数更少时更新记录，不把它称为全局最优解。

当前没有钥匙、单向门或必经检查点。这些会改变图的状态和唯一性定义，应在增加机制时一起修改检查器。

## 操作

鼠标、触屏点击白色空格放墙，再点深色墙移除。棋盘使用原生按钮，不依赖悬停或右键。圆圈格以虚线边框区分禁建通道；选中格子时，棋盘下方显示对应行列已用墙数和限额。

点击「进入挑战」直接打开首个未完成的挑战关，无需先通关入门。关卡列表按入门、挑战分组。小屏幕可以点击「放大棋盘」增加点按面积，并在棋盘区域横向滑动；方向键选格会让放大后的焦点保持可见。

可以用 `pages/only-path.html?level=challenge-crossroads` 直达第 9 关，其他关卡使用相应 ID。无效 ID 回退到存档关卡，切换关卡时更新当前地址。

键盘方向键选择格子，空格或 Enter 操作格子，Delete / Backspace 移除所选墙。C 检查、Z 撤销、Y 重做、R 清空；也支持 Ctrl / Command + Z，以及 Ctrl / Command + Shift + Z 重做。

清空本关可以撤销。历史最多保存 100 次编辑，仅存在当前页面；每关墙的位置、检查次数和通过方案保存在 `playroom.only-path.v1`。切换关卡或刷新后可以恢复草稿，通过方案另有恢复按钮。原有 8 关的 ID 和存档版本保持不变，新挑战使用独立 ID。浏览器禁止存储时仍可继续游玩，并显示保存失败提示。

## 如何判断唯一

`engine.js` 先检查放墙位置、总预算和行列限额，再把每个可行走格子（包含 `o`）当作顶点，四方向相邻关系当作无向边。指定路线 P 保持畅通，因此始终存在一个解。

依次临时删除 P 的每一条边，并做一次广度优先搜索：

1. 若仍然能从起点走到终点，搜索返回的简单路径就是另一条真实路线。
2. 若删除任何一条边后都无法到达终点，P 就是唯一的简单路径。

依据：任何不同于 P 的简单起终点路径，必然缺少 P 中的至少一条边；一条不重复顶点的路径不可能在保留 P 所有边的同时额外绕行。BFS 的已访问标记同时保证反例不会在死胡同里折返。

复杂度为 `O(|P| × (V + E))`。这里不枚举所有路径，也不会把“只有一条最短路”误当成“只有一条可行路线”。

## 编辑关卡

入门关卡位于 `src/games/only-path/levels.js`，挑战关卡独立放在 `src/games/only-path/challenge-levels.js`，最后统一解析。每个对象包含：

| 字段                       | 含义                                             |
| -------------------------- | ------------------------------------------------ |
| `id`                       | 唯一且稳定的关卡标识，存档引用它                 |
| `title` / `chapter`        | 中文标题和阶段                                   |
| `difficulty`               | `intro` 或 `challenge`，用于关卡选择分组         |
| `budget`                   | 正整数，最多可放置的墙数                         |
| `rowLimit` / `columnLimit` | 可选正整数，每行或每列的玩家墙数上限；省略则不限 |
| `description`              | 进入关卡时的简短说明                             |
| `hint`                     | 玩家主动展开的思路提示                           |
| `rows`                     | 等宽字符串组成的矩形棋盘，限制最大 9 × 9         |

字符约定：`#` 固定障碍、`.` 可放墙空地、`o` 可通行的禁建通道、`*` 蓝色路线、`S` 起点、`T` 终点。解析指定路线时只允许 `*ST`，不会把 `o` 当成蓝线。

```js
{
  id: 'my-level',
  title: '新的岔路',
  chapter: '观察',
  budget: 1,
  description: '保留蓝线，封住下面的绕路。',
  hint: '下方通道中的任意一格都可以切断绕路。',
  rows: ['#####', '#S*T#', '#.#.#', '#...#', '#####'],
}
```

必须恰好包含一个 S 和一个 T。S、T 与所有 `*` 要组成一条连续、无分叉、无额外相邻捷径的路径，解析器会拒绝不符合条件的数据。目标路线如果自身存在捷径，玩家无法在不可编辑的蓝色格子上修复它。

设计顺序建议：先确定指定路线，再添加绕路，保留一套在预算内的参考布局，最后考虑是否有更有意思的解法。不要把没有第二条路径的初始棋盘当作正常挑战关卡。

## 界面与发布

`renderer.js` 创建支持键盘焦点的 DOM 棋盘，并用同一套格子坐标绘制 SVG 蓝线和橙色虚线；缩放不改变路线坐标。格子颜色、线条样式、起终点文字、墙的叉号和障碍纹理共同区分状态。

页面入口为 `pages/only-path.html`，已经登记到 Vite 多页面构建和大厅目录。继续使用仓库现有的手动 GitHub Pages 工作流发布构建后的 `dist/`，不要直接把源码目录当作静态网站。

本次实现未编译、未构建、未运行游戏测试，也未进行浏览器验证。对触屏布局、实际游戏体验和关卡难度的判断仍需后续运行验证。
